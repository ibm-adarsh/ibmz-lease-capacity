Semantics

Lease occupancy model

A lease is taken when the job starts and stays busy through pre → test → post. Example: capacity 10 and one 3h hold leaves 9 leases free for those 3 hours. Heatmap cells show leases in use.

Weekly view

Concurrency heatmap

Each cell is concurrent leases in use during that UTC hour (most jobs hold 1 lease; some workflows hold more of the same type). Hold time = full job wall-clock (pre/test/post) + lease buffer.         Guide

        How to use this

        A short path through the page — what to look at first, and what the numbers mean.

        1. Pick a profile

        Use the tabs for the full cluster profile name (for example libvirt-s390x-vpn-amd64). Capacity comes from Boskos lease lists.

        2. Read the heatmap

        Each cell is leases in use that UTC hour. Available = total − in use. Click a cell to see which jobs overlap.

        3. Find free windows

        Best free windows and top free hours are the safest places to add or move jobs. Busiest hours show pressure.

        4. Check job hold times

        Lease hold is full job time (pre → test → post), usually from Sippy. Green/amber badges are source labels, not links — use Links for history.

        5. Older OCP versions

        If a version has no Sippy history, hold time is taken from the same job on another version. Sippy/Prow links open that version’s history.

        6. Low-frequency jobs

        Monthly or yearly jobs are listed in Inventory but stay out of the weekly heatmap so the grid stays readable.
