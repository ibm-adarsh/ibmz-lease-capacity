Semantics

Lease occupancy model

A Boskos lease is acquired when the job starts and stays held through pre → test → post (full Prow job wall-clock from Sippy, not test-phase only). Example: capacity 10, one job with a 3h lease hold ⇒ for the next 3 hours that lease is busy, so only 9 leases remain available for other jobs. Heatmap cell value = leases in use; available = capacity − in use.

        Guide

        How to read this

        • Profile tabs show the full cluster profile name (e.g. libvirt-s390x-vpn-amd64).
        • Prow cron times are UTC. Capacity comes from Boskos *-quota-slice name lists.
        • Each periodic acquires 1 lease at job start and keeps it for the full wall-clock (pre → test → post) after each cron start. Remaining capacity that hour = total leases − leases in use.
        • Duration source is Sippy full ProwJob average minutes (not test-only), biased toward the longer recent window when failures shorten the average, plus a small lease buffer; then workflow median; then the configured default.
        • low-frequency jobs (day-of-month / @yearly) are listed but excluded from the weekly heatmap.
        • This is a configured-schedule planning model, not live Boskos occupancy.
        • Dashboard refreshes daily at 08:00 IST from openshift/release (+ Sippy durations).
        • Raw data: jobs.csv · summary.json
